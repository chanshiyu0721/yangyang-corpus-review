# 秧秧语料 · 团队人工核验

用于鸣潮剧情陪伴 Agent 的秧秧语料清洗与人工核验。包含可填写审查页面、相关任务页章节证据、书信和语音等参考素材，以及已提交的人工意见。

## 开始核验

1. 点击仓库 **Code → Download ZIP**，解压到电脑。
2. 双击 `index.html`，用 Chrome 或 Edge 打开。GitHub 文件预览不会运行审查页面。
3. 填写自己的核验昵称；在“分工组”选择 A、B 或 C，再选择“未填写”或“仍不清楚”。三名成员各认领一组，避免重复劳动。
4. 核验任务剧情时看“正式任务全部”；书信、语音、飞讯和点位个人剧情看“非任务素材审查”。“排除归档”默认不需要继续核验。
5. 点击每项的任务页链接，对照目标台词、前文、选项和实际呈现方式，填写结论。
6. 完成一批后点击 **导出我的新增／改动**。请保留导出的 JSON；浏览器暂存不是团队同步。
7. 将 JSON 上传到仓库 `reviews/`，每人使用自己的文件名。没有仓库写权限的队友可通过 Fork 和 Pull Request 提交，或把文件交给汇总人。不要覆盖其他人的结果。

**页面没有后台，也不会把你的填写实时发送给队友。** “导出核验结果”可保存包含共同起点的完整个人备份；团队汇总优先使用“导出我的新增／改动”。

## 怎么填写才有用

- **处理意见**：已确认、仍不清楚、建议排除。没看清楚时选“仍不清楚”，并写缺少什么。
- **实际选项**：记录所选文字；确实没有选项才填“无”。点位触发、写信主题选择和口头问答需根据实际页面区分。
- **核验结论**：写清“保留哪段、修改什么、依据是什么”。不要只填“无”。仅确认了场景时，注明“顺序尚未核对”。
- **合并方式**：如果要合并，写清审查编号和顺序，例如“009→006”；不同分支、移动触发、人物插话和场景转换要分别判断。
- **场景**：区分秧秧视角、漂泊者视角、过去场景、幻境、内心活动、书信撰写与读信。发生在过去不等于秧秧在任意早期进度已经知道。
- **证据**：优先写任务名、节点/点位、前后台词编号，以及截图文件名或公开视频时间点。提交截图时放在 `reviews/evidence/` 下，并在结果中引用相对文件名。

书信、内心活动和日常口语分别保留标签。原有 `{TA}` 按已有人工作业视为用户名占位，不按性别猜填。正式版本按任务页实际展示正文筛选，页面采用的“二测／三测沿用”标签文本不会仅因标签而排除。

## 汇总队友结果

安装 Python 3 后，在解压目录运行：

```sh
python tools/merge_reviews.py reviews --output merged
```

工具校验清单版本、case_id 和原文编号，跳过各队友未改动的共同起点。不同人员对同一项给出不同结论时，保留全部意见并输出 `merged/conflicts.json`，不会用最后一个文件覆盖分歧。

- `merged/merged_review.json`：可导入页面继续核验；分歧项标为“仍不清楚”。
- `merged/review_history.json`：保留每项的全部来源文件与意见。
- `merged/conflicts.json`：需要汇总人裁定的分歧。
- `merged/summary.json`：汇总计数与处理记录。

原始结果始终留在 `reviews/`。相同人员再次提交时，保留历史并以该人员最新时间的记录作为其当前意见。每项“确认”仍需经过数据清洗与训练前复检，不自动批准训练。

## 来源与边界

任务文本来自玩家整理网站[瑝览类书](https://mc.yakitahome.com/story)，部分语音与书信素材来自[鸣潮灰机 Wiki](https://wuwa.huijiwiki.com/wiki/秧秧)。剧情与角色相关内容归相应权利人所有，本仓库用于非商业人工核验。仓库未对原始游戏文本授予额外许可。

`evidence/` 是 2026-10-27 获取的相关任务展示章节摘录，附源链接和源文件校验值，不包含完整网站备份。页面排列和文字顺序可以支持定位；具体选项跳转、角色可知范围与实际演出仍以核验记录为准。

上传包只保留核验所需文件，未包含原始大缓存、训练模型、凭据或本机路径清单。
